# Questions / Inputs for the Next Phase

The exact source is now integrated and Phase 0 Firebase removal is complete. The remaining questions are runtime/device/media inputs for the next phases.

## Device

1. **Exact Fire TV Stick 4K generation/model?**
   - Default: query it automatically with MCP `firetv_device_info` before the first test.

2. **Fire OS / Android API level?**
   - Default: query automatically; no assumption required.

3. **Is ADB over the LAN already enabled and reachable from the development PC/WSL host?**
   - Default: project provides `scripts/connect_firetv.sh` and MCP `adb_connect`.

## SageTV test content

4. **Which recording most reliably demonstrates the current skip/video problem?**
   - Needed before creating a high-level `test_seek_bug` tool.
   - Record filename/title, approximate problem timestamp and whether it is original/remuxed/transcoded.

5. **Which recording demonstrates slow video startup most reliably?**
   - If the same file does both, use it as the primary regression file.

6. **What codecs/containers need to be protected as regression cases?**
   Suggested initial set if available:
   - MPEG-2 TS
   - H.264 TS
   - H.264 MP4/MKV
   - HEVC/H.265
   - interlaced broadcast content
   - transcoded stream generated by SageTV

7. **Should Live TV/channel-change testing be included from the beginning?**
   - Default: no destructive/disruptive Live TV automation until playback-recording tests are stable.

## Player behavior

8. **Which player backend is currently selected/preferred in the MiniClient settings on the Fire TV: ExoPlayer, IJKPlayer, or automatic?**
   - Default: do not assume. Capture setting/runtime logs during baseline.

9. **Is preserving IJKPlayer a hard requirement, or can it eventually be removed if Media3 handles every real test file correctly?**
   - Default: preserve IJK until evidence says it is unnecessary.

10. **Do you want Media3 eventually to become the default player, or only an additional experimental backend at first?**
    - Recommended default: add/validate it experimentally first, then switch default after parity.

## Development app isolation

11. **Should the Dev development app share any settings/import mechanism with the existing installed MiniClient?**
    - Default: no. Separate Android application ID means separate app data, which protects the working installation.

12. **Does SageTV identify MiniClients/extenders in a way that requires a unique client ID/MAC-like identity per install?**
    - This needs inspection/runtime validation before both apps are used simultaneously against the server.
    - Default: do not copy private app data from the existing app.

## Automation scope

13. **Should Codex be allowed to automate navigation through the actual SageTV UI using remote key sequences?**
    - Recommended: yes for the development app only.

14. **Is an HDMI capture device worth adding later for pixel-level proof of rendered video?**
    - Default: no. Start with player/decoder telemetry + logs; add HDMI capture only if Surface/video capture limitations require it.

15. **Should failed test artifacts be retained indefinitely or rotated?**
    - Default: retain in `artifacts/firetv/` until a later cleanup policy is requested.

## Resolved Phase 0 decisions

- Firebase Analytics/Crashlytics and all identified orphan settings/preference UI are removed from `source/dev`.
- No replacement cloud analytics service will be added.
- `source/existing` remains the untouched comparison/build source.
