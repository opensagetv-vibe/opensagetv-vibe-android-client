SageTV MiniClient Dev v0.5.63

Purpose
- Give Codex/MCP exact event-time playback evidence instead of relying only on delayed host polling.
- Keep A/V recovery as the matrix verdict while making SageTV/server/player timeline relationships visible.

Android/debug changes
- debugStatusVersion=9.
- `MediaCmd` retains the latest SageTV MEDIACMD_SEEK target and sequence/timestamps.
- Server flush and post-flush Push anchor events also retain sequence/timestamps.
- `PlaybackEventTraps` keeps a debug-only 32-event ring.
- Event snapshots capture video rendered/queued counters, audio rendered/queued counters, AudioTrack playback head/session, decoder init/release counts, position, state, playing/loading, surface and decoder kind.
- Protocol events are timestamped immediately and snapshot asynchronously so diagnostics do not block the SageTV media-command thread.
- Exo2/Media3 use their existing Player.Listener; no continuous AnalyticsListener is added.

MCP changes
- New `dev_player_events` and `dev_clear_player_events` tools.
- `dev_player_state` exposes serverRequestedSeekMs plus server seek/flush/anchor timing and the latest event-trap summary.
- Full player matrix clears the trap ring before each action and stores exact event history in `eventTraps`.
- Counter reset-to-zero false PASS fixed; expected streams are latched pre-action.
- Seek position is diagnostic-only, default tolerance 10000 ms.
- Default slow-recovery threshold is now 5000 ms.

Verdict rule
- A/V recovered = PASS.
- Seek landing/timeline = diagnostic only; it may WARN/SUSPICIOUS but cannot fail a recovered video.

Validation
- Python/unit regression suite passes 117 tests in the handoff environment.
- `scripts/validate_project.py` passes with SAGETV_WORKSPACE set to the project root.
- Android Gradle compile could not be executed in this isolated environment because Gradle 8.13 was not cached and outbound download of services.gradle.org is unavailable. Rebuild/install on the normal Docker/WSL build host before device testing.
